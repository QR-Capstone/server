# 누리랩 최근 피싱주의보 및 ASK URL 목적지 사전 대조

출처: https://www.nurilab.com/kr/alert/phishing_alert
목록 요청: https://www.nurilab.com/kr/alert/paginate_alerts

기존 main.py의 warmup_engine() 호출을 이용하므로 공통 서버 변경이 필요 없습니다.
기본값은 한국시간 오늘 포함 최근 7일이며 KOBERT_NURILAB_DAYS=5 또는 6으로
범위를 줄일 수 있습니다. 5~7 이외 값은 7일로 처리합니다. 피싱과 사기 항목을 사용합니다.
목록 요청의 `detects=피싱,사기`로 두 유형을 함께 받아 원래 등록 유형을 보존합니다.

## 실행 흐름

1. 서버 예열 시 수집 스레드를 시작하고 모델 로딩과 동시에 첫 목록을 수집합니다.
2. 모델 연산 예열 후 첫 목록·목적지 수집 완료를 추가로 최대 37초 기다립니다.
   수집 실패·시간 초과여도 서버의 모델 준비를 막지 않습니다.
3. 첫 수집 이후 검사 요청이 없어도 정상 수집 완료 기준 3,600초 뒤 갱신합니다.
4. 누리랩 목록 갱신 실패 시 목록을 비우고 60초 뒤 재시도합니다.
   ASK URL 목적지 조회만 실패하면 원래 목록을 유지하며 미완료 항목을 재시도합니다.
   HTTP 429는 Retry-After를 따르고, 없으면 5분부터 재시도 간격을 늘립니다.
   성공한 자료는 메모리 캐시를 재사용합니다. 확인 완료 후 1시간 주기로 복귀합니다.
5. 검사 URL은 모델 초기화·공식 도메인 허용 검사·사이트 수집 전에 메모리 목록과 대조합니다.
   하위 링크도 해당 페이지를 수집하기 전에 대조합니다. 일치 시 악성 판정을 확정하고
   해당 URL의 본문 수집과 KoBERT 독립 추론을 추가 수행한 후, 기존 JSON 구조로
   unnormal/HIGH와 threat_score=100.0을 반환합니다. 화이트리스트·오류 문구·폼 목적지
   규칙에 의한 조기 반환은 이 일치 경로에서 적용하지 않습니다.
   목록 일치 URL의 하위 링크를 재귀적으로 검사하지는 않습니다.
6. 목록 미준비·만료·불일치·비활성화 시 기다리거나 새 다운로드를 시작하지 않고
   기존 KoBERT 수집·추론 경로로 진행합니다.

누리랩 목록은 우선 준비하고, 검증한 ASK URL 최종 목적지를 메모리에 추가합니다.
갱신 중 유효한 기존 목적지 기록도 조회할 수 있으나 새 결과가 준비되면 교체합니다.
목록 메모리는 성공 수집 후 3,637초가 지나면 사용하지 않습니다(1시간 + 초기 준비 여유 37초).
자정에도 항목의 게시일을 다시 확인하여 5~7일 범위 밖의 URL은 제외합니다.
조회 시 네트워크 작업은 없으며 짧은 메모리 잠금과 URL 정규화만 수행합니다.
목록 일치 때도 캐시가 없으면 본문 수집과 추론을 기다리므로 기존의 즉시 반환보다 시간이 늘어납니다.
응답은 지정 문구와 모델 결과를 한 JSON에 담아 한 번 반환하며 중간 응답을 보내지 않습니다.

## 대조 범위와 안전한 수집

목록 수집기는 공식 누리랩 목록·상세 게시물 및 ASK URL의 기존 공개 summary 결과만
GET으로 조회하며 게시된 악성 사이트나 단축 주소에는 접근하지 않습니다.
다만 사용자가 검사 요청한 URL(또는 선별된 하위 URL)이 목록에 일치하면,
탐지 엔진이 그 대상 페이지를 기존 HTTP/Playwright 수집 함수로 분석합니다.
검사 대상 URL을 누리랩으로 전송하지 않습니다. 로그인·쿠키·새 스캔 제출은 사용하지 않습니다.
응답 리다이렉트는 거부하며 파일 캐시 없이 프로세스 메모리에만 저장합니다.
누리랩 상세 게시물은 확인된 공식 확장자 없는 주소를 직접 사용합니다.
누리랩 목록 수집 예산은 12초, 요청당 타임아웃은 최대 4초, 최대 10페이지입니다.
목적지 보완은 20초 예산·최대 2개 동시 요청으로 수행하고 단축 주소를 우선합니다.
원격 응답이 지연될 경우에도 서버의 추가 초기 대기는 최대 37초 후 종료됩니다.

URL은 [.] 등 비활성 표기를 복원하고 호스트 대소문자·IDNA·기본 포트 등을 정리합니다.
스킴·경로·쿼리·프래그먼트를 보존한 정확한 URL 대조입니다. 전체 도메인이나
하위 도메인을 일괄 차단하지 않으며 생략 표시가 있는 URL은 사용하지 않습니다.
피싱 등록 여부를 반영하는 것이며 사이트의 현재 생존 여부 확인은 아닙니다.
최종 리포트의 100점은 목록 일치 정책값으로 모델 확률이 아닙니다.
수집기의 내부 기본 리포트는 그대로 두고 koBERT.py에서 최종 100점으로 설정합니다.
별도 계산한 KoBERT 악성 클래스 점수는 룰 보정 전 softmax 출력입니다.
이 값이 낮거나 추론이 실패해도 목록 일치 판정은 정상으로 바뀌지 않습니다.

## 설정·확인

- KOBERT_NURILAB_ENABLED=0: 비활성화. 기본은 1입니다.
- KOBERT_NURILAB_DAYS=5: 오늘 포함 5일. 기본은 7입니다.
- python KoBERT/nurilab_feed.py --refresh: 누리랩 최근 목록과 ASK URL 목적지 사전 수집을 확인합니다.
- python KoBERT/check_ready.py: 기존처럼 외부 접속 없는 모델 점검입니다.
  이 점검 프로세스에서는 누리랩 기능을 끕니다. 실제 서버의 환경 변수에는 영향을 주지 않습니다.
- 서버 로그의 '[누리랩] 최근 7일 목록 N개 준비 완료 (1시간마다 갱신)'를 확인합니다.
- '[누리랩 + ASK URL] 등록 N개, 추가 목적지 M개, 확인 미완료 K개'도 확인합니다.
  미완료 항목의 목적지는 아직 일치하지 않을 수 있으며 원래 등록 주소 대조는 유지됩니다.

기존 /ready의 ready=true는 모델 준비 상태입니다. 누리랩이 실패해도 기존 분석을
제공하므로 피드 준비까지 보장하는 값이 아닙니다. 피드 성공/실패는 서버 로그로 확인합니다.
여러 서버 프로세스를 실행하면 각 프로세스가 자체 목록과 갱신 스레드를 갖습니다.
서버 종료 시 데몬 스레드는 함께 종료되며 stop_background_refresh()로 명시적으로
종료할 수도 있습니다. OS 작업 스케줄러나 별도 Codex 자동화는 필요 없습니다.

공개 웹앱의 비공식 조회 엔드포인트를 사용하므로 누리랩·ASK URL 응답 구조가 바뀌면 수집기 수정이
필요할 수 있습니다. main.py, 다른 모델, .pt, 토크나이저 및 기존 판정 문자열은 변경하지 않습니다.

## 사용자 표시 문구

목록과 일치하면 기존 `evidence.ai_semantic_evidence.ai_inference_logic`에
"해당 사이트는 이미 기록되어있는 피싱 사이트입니다. 접속을 삼가해주세요."를 먼저 넣고,
같은 문자열 뒤에 KoBERT의 독립 악성 클래스 점수와 수집 본문 발췌를 덧붙입니다.
본문 발췌는 입력 내용의 참고 자료이며 어텐션 기반 설명이나 악성의 증명이 아닙니다.
이 경로는 점수 계산에 어텐션 출력을 요청하지 않아 추가 설명용 연산을 줄입니다.
404/보안 경고 화면도 텍스트가 확보되면 그 화면을 분석한 점수를 반환합니다.
이는 원래 피싱 본문을 복원한 결과가 아닙니다.
본문이 없거나 수집·모델 실행에 실패하면 점수를 만들어내지 않고
"KoBERT 추가 분석 불가"와 사유를 덧붙입니다. 악성 판정과 지정 문구는 유지합니다.
출처와 게시일은 기존 `evidence.heuristic_evidence.rule_trigger`에 남깁니다.
새 JSON 필드는 추가하지 않습니다. 앱이 다른 필드를 표시한다면 앱의 연결은
별도 확인이 필요하며 이 변경에서는 공통 서버나 앱을 수정하지 않습니다.

## ASK URL 최종 목적지 연결

누리랩 상세 게시물이 연결하는 `https://askurl.io/urls/<64자리 ID>` 결과에서 원래 URL,
최종 URL, 분석 시각을 읽습니다. 원래 URL이 누리랩 항목과 정확히 일치하고 공개 분석 분류가
피싱/사기일 때만 최종 URL을 대조 목록에 추가합니다. 현재 연결 상태를 새로 검사하지 않습니다.
등록 주소와 목적지는 모두 기존 목록 일치 정책을 사용하며, 목적지 일치 근거에는 원래 주소,
공개 분석 시각과 ASK URL 출처를 함께 기록합니다. 원래 누리랩 게시일이 기간 밖이면 목적지도 만료됩니다.
다른 경로·쿼리·스킴이나 도메인 전체, 중간 경유지를 일괄 악성으로 등록하지 않습니다.
ASK URL 로그인·새 분석 제출·URL 생존 확인 API는 사용하지 않습니다.

## 접근 제한 안내 처리

`Page not available` 등 짧은 접근 제한 안내만 있고 실제 본문이 없으면 KoBERT 추론을 생략합니다.
등록 이력이 없는 URL은 기존 `unknown/UNKNOWN` 판정과 evidence 필드로 분석 불가를 반환합니다.
누리랩 원본 또는 확인된 목적지가 일치하면 `unnormal/HIGH/100.0`을 유지하면서 아래 문구를 덧붙입니다.

> 접근 제한 안내가 표시되어 실제 본문을 확보하지 못했습니다. KoBERT 문맥 분석을 수행할 수 없습니다. 접근에 유의해주시길 바랍니다.

일반 본문에서 해당 표현을 인용한 경우는 이 규칙에 해당하지 않습니다. 하위 페이지에
안내문만 있고 다른 검사에서 악성이 확인되지 않았다면 최종 결과를 unknown으로 반환합니다.
분석 불가 결과와 목록 일치 후 추가 분석 불가 결과는 URL 결과 캐시에 저장하지 않습니다.

## 키워드 문장 선별

`focus_keywords.json`에 있는 키워드 문장과 주변 문맥을 본문 길이 제한 전에 선별합니다.
최대 3개 영역을 원문 순서로 유지하고 기존 본문 500자·최종 1000자·512토큰 제한을 유지합니다.
가중치·토크나이저·룰 점수 자체는 바꾸지 않지만 모델 입력이 달라져 예측 점수는 달라질 수 있습니다.
정확도 향상이 검증되었다는 의미는 아닙니다. 키워드가 없으면 기존 선두 텍스트 방식을 사용합니다.
`KOBERT_FOCUS_ENABLED=0`으로 선별만 끌 수 있고 기본값은 1입니다. 키워드 목록 수정 후 재시작하세요.
기능 켬/끔은 서로 다른 URL 결과 캐시 키를 사용합니다.

누리랩 탐지 유형이 **사기**인 URL과 일치하면 위 피싱 문구 대신
**"사기 사이트로 등록된 이력이 있는 사이트입니다."**를 사용합니다.
이 경우 `threat_type`은 `사기 사이트`이며 최종 `unnormal/HIGH`, `threat_score=100.0`은
피싱 등록 URL과 같습니다. 사기 URL도 본문을 수집해 KoBERT 독립 점수를 설명에 붙이며,
실패하면 사기 안내 문구와 추가 분석 불가 사유를 함께 반환합니다.
메인 URL과 선별된 하위 URL에 모두 적용합니다. 과거 전체 이력이 아니라 설정된 최근 5~7일
목록을 대상으로 하며, JSON 필드 구조 및 normal/unnormal/unknown 판정값은 유지합니다.
이번 분류 확장은 `koBERT.py`와 `nurilab_feed.py`를 함께 배포하고 프로세스를 재시작해야 합니다.

## URL 검사 결과 캐시 (2026-11-24)

`koBERT.py`의 `predict_phishing_result()`는 같은 URL의 완료된 정상/악성 결과를
프로세스 메모리에 기본 2시간 저장합니다. 동일 URL을 재요청하면 페이지 수집과 모델 추론을
다시 하지 않고 결과 사본을 반환합니다. 문장만 검사하는 모드는 이 캐시를 사용하지 않습니다.

- `KOBERT_RESULT_CACHE_HOURS=1` / `2` / `3`: 보관 시간. 1~3시간 사이 소수도 가능하며,
  범위 밖이거나 잘못된 값이면 기본 2시간입니다. 재조회해도 만료 시각은 연장하지 않습니다.
- `KOBERT_RESULT_CACHE_ENABLED=0`: 캐시를 끕니다. 기본은 `1`입니다.
- 최대 256개 URL 결과를 보관하며, 한도를 넘으면 가장 오래 사용하지 않은 항목을 제거합니다.
- URL 전체 문자열로 구분합니다. 경로·쿼리·스킴·프래그먼트가 다른 URL은 합치지 않습니다.
  브라우저 사용 설정·입력 길이·HTTP 타임아웃·누리랩 설정·로드된 모델이 바뀌면 분리합니다.
- `unknown`, 초기화/추론 오류, 누리랩 일치 후 추가 분석 불가 결과는 저장하지 않습니다.
  선별한 하위 페이지 중 유효 본문을 얻지 못한 페이지가 있으면 그 요청 결과도 저장하지 않습니다.
- 캐시 반환 전 메인 URL과 이전 검사에서 확인한 하위 URL의 현재 누리랩 메모리 목록을
  다시 대조합니다. 등록·삭제·게시 정보 변경·목록 만료로 대조 결과가 달라지면 재검사합니다.
  목록 갱신 자체는 기존 1시간 주기이며, 검사 요청마다 누리랩에 접속하지 않습니다.
- 누리랩 등록 URL의 정상적인 추가 분석 결과도 캐시할 수 있습니다. 재요청 시 100점 정책값과
  지정 문구, 이전 KoBERT 점수를 함께 재사용합니다. 원본 JSON 필드와 판정 문자열은 그대로입니다.
- 캐시 사용 여부는 `[KoBERT 캐시] URL 결과 재사용` 로그로 표시합니다. JSON에 필드를 추가하지 않습니다.
- 서버/프로그램 재시작 시 비워집니다. 실행 중 명시적으로 비우려면 `clear_result_cache()`를 호출합니다.
  여러 서버 프로세스 사이에서 캐시는 공유하지 않습니다. 동시 최초 요청을 하나로 합치는 기능은 없습니다.

캐시 기간에는 페이지 본문만 바뀐 사실을 즉시 알 수 없으므로, 새 결과가 필요하면 캐시를 끄거나
비우고 검사하세요. 누리랩 목록과 URL 결과 캐시는 별개이며, 이 기능은 모델 정확도 개선이 아니라
반복 URL 검사에서 수집·추론 비용을 줄이기 위한 기능입니다.

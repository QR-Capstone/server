# 누리랩 최근 피싱주의보 사전 대조

출처: https://www.nurilab.com/kr/alert/phishing_alert
목록 요청: https://www.nurilab.com/kr/alert/paginate_alerts

기존 main.py의 warmup_engine() 호출을 이용하므로 공통 서버 변경이 필요 없습니다.
기본값은 한국시간 오늘 포함 최근 7일이며 KOBERT_NURILAB_DAYS=5 또는 6으로
범위를 줄일 수 있습니다. 5~7 이외 값은 7일로 처리합니다. 피싱 항목만 사용합니다.

## 실행 흐름

1. 서버 예열 시 수집 스레드를 시작하고 모델 로딩과 동시에 첫 목록을 수집합니다.
2. 모델 연산 예열 후 첫 수집 완료를 추가로 최대 13초 기다립니다.
   수집 실패·시간 초과여도 서버의 모델 준비를 막지 않습니다.
3. 첫 수집 이후 검사 요청이 없어도 정상 수집 완료 기준 3,600초 뒤 갱신합니다.
4. 갱신 실패 시 목록을 비우고 60초 뒤 재시도합니다. 성공하면 1시간 주기로 복귀합니다.
5. 검사 URL은 모델 초기화·공식 도메인 허용 검사·사이트 수집 전에 메모리 목록과 대조합니다.
   하위 링크도 해당 페이지를 수집하기 전에 대조합니다. 일치 시 기존 JSON 구조로
   unnormal/HIGH를 반환하고 그 URL의 수집과 모델 추론을 생략합니다.
6. 목록 미준비·만료·불일치·비활성화 시 기다리거나 새 다운로드를 시작하지 않고
   기존 KoBERT 수집·추론 경로로 진행합니다.

새 목록은 별도로 수집한 후 메모리에서 한 번에 교체합니다. 갱신 중 기존 목록은
조회할 수 있으나 성공 수집 후 3,612초가 지나면 사용하지 않습니다(1시간 + 수집 예산 12초).
자정에도 항목의 게시일을 다시 확인하여 5~7일 범위 밖의 URL은 제외합니다.
조회 시 네트워크 작업은 없으며 짧은 메모리 잠금과 URL 정규화만 수행합니다.
전체 검사 시간이 항상 같거나 빨라진다는 보장은 없으며 목록 일치 때 수집/추론을 생략합니다.

## 대조 범위와 안전한 수집

공식 누리랩 목록 엔드포인트만 조회하며 게시된 악성 사이트에는 접근하지 않습니다.
검사 대상 URL을 누리랩으로 전송하지 않습니다. 로그인·쿠키·새 스캔 제출은 사용하지 않습니다.
목록 응답 리다이렉트는 거부하며 파일 캐시 없이 프로세스 메모리에만 저장합니다.
기본 수집 예산은 12초, 요청당 타임아웃은 최대 4초, 최대 10페이지입니다.
원격 응답이 지연될 경우에도 서버의 초기 대기는 최대 13초 후 종료됩니다.

URL은 [.] 등 비활성 표기를 복원하고 호스트 대소문자·IDNA·기본 포트 등을 정리합니다.
스킴·경로·쿼리·프래그먼트를 보존한 정확한 URL 대조입니다. 전체 도메인이나
하위 도메인을 일괄 차단하지 않으며 생략 표시가 있는 URL은 사용하지 않습니다.
피싱 등록 여부를 반영하는 것이며 사이트의 현재 생존 여부 확인은 아닙니다.
99점은 목록 일치 정책값으로 모델 확률이 아닙니다.

## 설정·확인

- KOBERT_NURILAB_ENABLED=0: 비활성화. 기본은 1입니다.
- KOBERT_NURILAB_DAYS=5: 오늘 포함 5일. 기본은 7입니다.
- python KoBERT/nurilab_feed.py --refresh: 누리랩 연결과 최근 목록 수집만 확인합니다.
- python KoBERT/check_ready.py: 기존처럼 외부 접속 없는 모델 점검입니다.
  이 점검 프로세스에서는 누리랩 기능을 끕니다. 실제 서버의 환경 변수에는 영향을 주지 않습니다.
- 서버 로그의 '[누리랩] 최근 7일 목록 N개 준비 완료 (1시간마다 갱신)'를 확인합니다.

기존 /ready의 ready=true는 모델 준비 상태입니다. 누리랩이 실패해도 기존 분석을
제공하므로 피드 준비까지 보장하는 값이 아닙니다. 피드 성공/실패는 서버 로그로 확인합니다.
여러 서버 프로세스를 실행하면 각 프로세스가 자체 목록과 갱신 스레드를 갖습니다.
서버 종료 시 데몬 스레드는 함께 종료되며 stop_background_refresh()로 명시적으로
종료할 수도 있습니다. OS 작업 스케줄러나 별도 Codex 자동화는 필요 없습니다.

공개 목록의 비공식 엔드포인트를 사용하므로 누리랩 응답 구조가 바뀌면 수집기 수정이
필요할 수 있습니다. main.py, 다른 모델, .pt, 토크나이저 및 기존 판정 문자열은 변경하지 않습니다.

## 사용자 표시 문구

목록과 일치하면 기존 `evidence.ai_semantic_evidence.ai_inference_logic`에
"해당 사이트는 이미 기록되어있는 피싱 사이트입니다. 접속을 삼가해주세요."를 반환합니다.
출처와 게시일은 기존 `evidence.heuristic_evidence.rule_trigger`에 남깁니다.
새 JSON 필드는 추가하지 않습니다. 앱이 다른 필드를 표시한다면 앱의 연결은
별도 확인이 필요하며 이 변경에서는 공통 서버나 앱을 수정하지 않습니다.

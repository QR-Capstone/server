## 서버 실행

기존처럼 서버 시작 시 `warmup_engine()`에서 한 번 불러옵니다.
`main.py`, XGBoost, GNN, JSON 키·판정 문자열·룰 기반 점수 보정은 변경하지 않았습니다.
가중치는 기존 위치 `KoBERT/kobert_phishing_model_weights.pt`에 있고 Git LFS로 관리합니다.
배포 시 `git lfs pull`로 실제 가중치를 받아야 합니다.

`model_assets/`에는 학습에 사용한 config, SentencePiece 토크나이저, 전처리와
`training.json`이 있습니다. `model_runtime.py`는 인터넷에서 다른 버전을 받지 않고
이 파일들로 모델을 만들고, 해시·클래스·어휘 정보와 가중치를 확인합니다.
설정/파일 불일치 시 예열 단계에서 실패하며 기존 토크나이저로 자동 대체하지 않습니다.
기존 서버의 eager attention과 증거 문장 추출 인터페이스를 유지합니다.

HTML에서 추출한 본문은 학습과 공유하는 `prepare_text()`로 한 번 처리합니다.
기존 끝단 처리와 같은 공백 정리·1,000자 제한·마스킹을 사용합니다.
이 후보의 `focus_enabled=false`에 맞게 고위험 문장을 앞에 중복 삽입하는 단계는
제거했습니다. 고위험 키워드 기반 점수 보정과 증거 문장 선택은 유지합니다.

## 다음 재학습 결과 적용

같은 모델 구조·토크나이저·전처리·클래스 순서·512토큰 설정으로 재학습했다면:

1. 새 `.pt`를 `kobert_phishing_model_weights.pt`로 교체합니다.
2. 같은 실행 결과의 `training.json`을 `model_assets/training.json`으로 교체합니다.
3. config와 tokenizer 및 preprocessing 파일이 기존과 같은지 확인합니다.
4. 서버를 재시작하고 `/ready`의 KoBERT 로딩/예열 상태를 확인합니다.

토크나이저가 동일하면 매번 다시 교체할 필요가 없습니다. `.pt`만 교체하고
`training.json`을 그대로 두면 가중치 해시 검사에 실패합니다.
구조·전처리·토크나이저를 변경한 학습은 관련 자산과 로더 호환성을 다시 검토해야 합니다.

## 이 후보의 평가 범위

사용자가 제공한 최신 ZIP은 최종 통합 CSV 정상 1,812건·악성 1,812건,
총 3,624건을 입력으로 사용했습니다. 입력 파일의 SHA-256도 로컬 최종본과 일치합니다.
학습 2,580건(각 1,290), 검증 522건(각 261), 시험용 522건(각 261)으로 분리되었고,
최적 가중치는 5번째 에폭입니다. 제외 및 중복 제거는 0건입니다.

학습 기록의 검증 결과(임계값 0.5)는 정확도 98.47%, 악성 재현율 98.08%,
정상 오탐률 1.15%, macro-F1 0.9847입니다. 혼동행렬은 [[258, 3], [5, 256]]입니다.
이는 모델 선택에 사용한 검증 결과이며 독립 시험 성능이 아닙니다.
`status=trained_not_tested`로 최종 시험은 아직 실행되지 않았습니다.
실제 자료와 합성 문구가 포함된 데이터의 검증 점수를 운영 사이트의 탐지 성능으로
일반화할 수 없으며, 이전 운영 모델과의 독립 비교 결과는 아직 없습니다.
ZIP에 제안된 임계값은 서버에 적용하지 않았습니다. 기존 판정 기준을 유지합니다.

이번 갱신에서 config·토크나이저·전처리는 이전 후보와 바이트 단위로 동일함을
확인했습니다. `.pt`와 짝이 되는 `training.json`만 교체하며 실행 코드와 JSON은
그대로 유지합니다. 원시 검증 예측 CSV와 학습 데이터는 공개 저장소에 추가하지 않습니다.

학습은 transformers 5.5.4 / sentencepiece 0.2.1로 수행되었습니다.
공용 requirements를 바꾸지 않았으므로 배포 서버의 설치 버전에서도 확인해야 합니다.

## 로컬 검증

`python -m unittest discover -s KoBERT/tests -v`

테스트는 저장된 실제 가중치를 사용하며 외부 사이트에 접속하지 않습니다.
JSON 형식 유지, 중복 전처리 방지, 예열 후 모델 재사용, 모델 자산 불일치 차단과
학습 시 검증 점수의 재현을 확인합니다. 검증 점수 재현 테스트는 비공개 JSON 파일의
경로를 `KOBERT_VALIDATION_SAMPLES` 환경 변수로 지정한 경우에만 실행합니다.
각 항목에는 `text`, `label`, `probability`가 필요합니다. 원본 검증 문구는 저장소에
포함하지 않으며, 기본 JSON 테스트는 별도로 작성한 예문을 사용합니다.
전체 FastAPI 배포/GPU 테스트를 대신하지 않습니다.

## 서버 시작 전 준비 확인 (2026-10-26 보강)

공통 `main.py`는 수정하지 않습니다. 기존 `startup_event()`가 이미
`await _run_engine(app.state.eng.warmup_engine, STARTUP_WARMUP_PLAYWRIGHT)`를
호출하므로, 이 PR의 `KoBERT/` 파일을 배포하면 새 로더가 자동으로 실행됩니다.
아직 기본 브랜치에 병합되지 않은 PR이라면 해당 코드부터 배포해야 합니다.
기존 `.pt`만 교체해서는 새 로더가 적용되지 않습니다.

서버 담당자는 저장소 루트에서 서버와 같은 Python 환경으로 실행합니다.

```bash
git lfs pull --include="KoBERT/kobert_phishing_model_weights.pt"
python KoBERT/check_ready.py
```

`[KoBERT READY]`와 종료 코드 0은 로컬 가중치·토크나이저·설정 검증,
512토큰 실제 연산과 객체 재사용 검사가 통과했다는 뜻입니다.
파일 불일치나 연산 오류 시 종료 코드 1로 실패합니다. 이 명령은 URL에
접속하거나 브라우저를 실행하지 않습니다. 전체 모델의 정확도 검사는 아닙니다.
이 점검 프로그램이 종료되면 메모리는 반환됩니다. 서버 프로세스는 시작 시
자체 모델을 다시 준비하므로 점검 명령을 서버 예열의 대체로 사용하지 않습니다.

기존 방식으로 서버를 시작한 후 `/ready`의 `ready=true`,
`warmup_done=true`, `warmup.model_loaded=true`를 확인합니다.
수동 `/warmup`을 반복하면 기존 응답처럼 `status=already_initialized`가
표시될 수 있습니다. `/health`의 200만으로 모델 준비 완료를 판단하지 않습니다.
`/ready`는 HTTP 200이더라도 본문의 `ready`가 false일 수 있으므로 값을 확인합니다.
기존 main.py는 예열 실패 후에도 서버를 실행하므로 준비 상태를 확인한 뒤
검사 요청을 전달해야 합니다. 이 PR은 공통 서버의 요청 차단 정책을 바꾸지 않습니다.

초기화 락으로 동시 호출 시 중복 로딩을 막고, 512토큰·attention 출력의 실제
추론 경로를 예열합니다. 예열이 성공한 후에만 전역 모델을 공개하고 준비 상태를
설정합니다. 초기화가 실패한 경우 준비 상태를 설정하지 않으며 재시도할 수 있습니다.
이 보강은 서버 시작 시 비용이며, 이후 검사 요청에서 파일 해시 검사와 모델 로딩을
반복하지 않습니다. 모델/JSON 판정 규칙과 `.pt` 내용은 이 보강에서 바꾸지 않았습니다.

준비 완료는 KoBERT 텍스트 모델 기준입니다. 선택적인 Playwright 준비는 별도이며
브라우저 준비나 외부 사이트 수집 성공을 보장하지 않습니다. 여러 서버 프로세스를
사용하면 각 프로세스가 모델을 한 번씩 로딩하여 메모리를 각각 사용합니다.
